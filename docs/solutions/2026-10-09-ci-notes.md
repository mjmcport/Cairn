# CI notes

## What we learned

- **The `macos-26` runner has Xcode 26.6 at `/Applications/Xcode_26.6.app`**, and Homebrew for installing XcodeGen. The workflow passed on its first run with no runner-specific changes, because the Makefile already took `DEVELOPER_DIR` from the environment.
- **XCUITest works on the hosted runner** without extra setup. The four end-to-end tests and the signpost-based performance test all ran.
- **Branch protection and rulesets need GitHub Pro on a private repository.** The API answers 403. Without it, a pull request with a failing check shows red but GitHub still reports it as `MERGEABLE` (`UNSTABLE`).
- **Trial a workflow on a branch with a draft pull request** before it lands on `main`. The `pull_request` trigger runs the workflow from the branch, so `main` never carries a broken workflow.
- **The hosted runner (VirtualMac2,1) is 40% to 85% slower than the M4 reference Mac** on listing and sorting, yet faster on detail metadata. Cross-machine timing comparisons are meaningless; the comparison tool now refuses to judge them.
- **A run takes about 5 minutes**, which costs about 50 billed minutes on a private repository because macOS minutes count ten times.
- **`tee` into a folder that a later command creates fails.** Create the folder before the pipeline.

## What to carry forward

- When the repository goes public or the account moves to GitHub Pro, run `scripts/protect-main.sh`, then repeat the failing-pull-request test and tick the two open items in the step 9 plan.
- To gate on performance in CI, record a second baseline on the runner model and compare runner runs against that one.
- Step 12 adds the build artifact upload to this workflow.
